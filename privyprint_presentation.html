Project Abstract

PrivyPrint is a decentralized application (dApp) designed to eliminate the privacy and security vulnerabilities inherent in the physical document printing pipeline. By leveraging AES-256 client-side encryption, IPFS for decentralized ciphertext storage, and a Solidity smart contract for on-chain access governance, PrivyPrint ensures that sensitive documents are never stored in plaintext on any central server, mail client, or print shop hard drive. The document remains completely encrypted from sender to paper — only the designated print shop's wallet can decrypt it, and only ephemerally in browser memory during the print operation.

Built with Next.js 15, Ethers.js v6, and a premium glassmorphic UI, PrivyPrint bridges the gap between digital-to-physical media security for a modern, privacy-conscious audience.

Section 01

Problem Definition & Ethical Framework

Why secure printing matters, who it affects, what's broken, and how Web 3.0 can fix it.

🎯
Detailed Problem Statement

"There currently exists no standardized, secure, and decentralized method for transmitting highly confidential digital documents to third-party physical printing facilities without exposing document contents in plaintext to intermediate transit networks, centralized database hosting providers, or persistent storage drives at the target print location."

Why the Problem is Important

  • Identity Theft: Bank statements, tax filings, government IDs, and medical records are routinely printed. Files left on print shop hard drives are high-value targets for data harvesting.
  • Corporate Espionage: Financial audits, patent drafts, merger agreements, and board resolutions are vulnerable to insider leaks at commercial print terminals.
  • Legal Compliance: Regulations like GDPR (Europe), HIPAA (US), and DPDP (India) mandate PII protection throughout its entire lifecycle. Accumulating plaintext files violates these frameworks.
  • No Revocation Mechanism: Once a document is emailed or uploaded, senders cannot reliably "un-send" or delete it from a third-party's system.

👥
Target Users

Individual Senders

Privacy-conscious consumers printing personal documents: medical records, legal agreements, tax filings, bank statements.

Enterprise Senders

Organizations requiring secure external printing of proprietary data and confidential client files.

Print Shop Operators

Print business owners wanting to offer a verified, secure service without taking on the liability of storing sensitive client files.

⚠️
Existing Limitations

  • Cloud Storage (Drive/Dropbox): Files are decrypted on provider servers. Permissions must be manually managed.
  • Encrypted Email (ProtonMail): Not optimized for commercial print terminals. Operators still download plaintext PDFs to disk.
  • SFTP / Managed File Transfer: Secures transit but stores plaintext at rest. No revocation or audit trail.
  • DRM Clients: Require proprietary software installations. Not compatible with public print shops.

🌐
Web 3.0 Relevance & Decentralization

Trustless Access Mediation

Instead of trusting a centralized database to manage print permissions, a Solidity smart contract enforces access rules immutably on-chain.

Cryptographic Sovereignty

The document's AES key is wrapped specifically for the print shop's wallet address using asymmetric ECIES encryption.

Immutable Audit Trail

The blockchain logs job creations, cancellations, and completions. This audit trail cannot be modified by either party.

Zero-PII Backend

MongoDB caches only public directory information. IPFS stores only encrypted ciphertext that is cryptographically unreadable without the AES key.

Core Data Structures

enum JobStatus { Pending, Completed, Revoked } struct PrintJob { uint256 id; // Unique on-chain job ID string cid; // IPFS Content Identifier of encrypted file address sender; // Wallet address of document owner address receiver; // Wallet address of designated print shop uint256 expiry; // Unix timestamp of access expiration uint256 copies; // Number of copies requested string printType; // "Color" or "Black & White" string encryptedKey; // AES key wrapped with shop's public key JobStatus status; // Current lifecycle state }

Key Contract Functions

// Print shop registers their wallet's public key on-chain function registerEncryptionKey(string publicKey) external; // Sender creates a print job with encrypted payload reference function createPrintJob(cid, receiver, expiry, copies, type, encryptedKey) → uint256; // Print shop confirms and marks job done (must be before expiry) function confirmPrint(uint256 jobId) external; // Sender revokes access before printing (instantly blocks shop) function revokeAccess(uint256 jobId) external;

Encryption Algorithms & Modules

Symmetric File Encryption (AES-256-CBC)

// lib/encryption.ts export async function encryptFile(file, accessKey) { const dataUrl = await fileToDataUrl(file); const encrypted = CryptoJS.AES .encrypt(dataUrl, accessKey).toString(); return new Blob([encrypted], { type: 'text/plain' }); }

Asymmetric Key Wrapping (x25519-xsalsa20)

// Encrypt AES key with shop's MetaMask public key export function encryptAccessKeyForReceiver( accessKey, receiverPublicKey ) { const encrypted = encrypt({ publicKey: receiverPublicKey, data: accessKey, version: 'x25519-xsalsa20-poly1305' }); return `0x${Buffer.from(JSON.stringify(encrypted)).toString('hex')}`; }

Direct Print — In-Memory Revocation

// In PrintInterface.tsx — Document NEVER saved to disk const blobUrl = URL.createObjectURL(decryptedBlob); // RAM only iframe.src = `${blobUrl}#toolbar=0&navpanes=0`; // Sandboxed iframe.contentWindow.print(); // Trigger OS print URL.revokeObjectURL(blobUrl); // PURGE from RAM

⚡
Scalability & Security

Scalability

  • Client-side encryption offloads compute from servers entirely.
  • IPFS provides horizontally scalable decentralized storage.
  • Smart contract interactions require minimal on-chain state, keeping gas costs low.

Security Controls

  • HTTPS, CSP headers, iframe sandboxing.
  • Automatic Blob URL revocation after print.
  • bcrypt-hashed passwords (10 salt rounds).
  • JWT session tokens via NextAuth.js.

Limitations

  • PDFs > 50MB may exceed browser memory limits during client-side encryption.
  • Requires MetaMask browser extension.
  • Depends on IPFS gateway availability (Pinata).
Section 03

Interface Design & User Experience

User flows, navigation, visual design, responsiveness, accessibility, and Web3 abstraction.

📤
Sender: End-to-End User Interaction Flow

1
Visit Landing Page & Connect Wallet
User visits PrivyPrint, reads the security overview, and clicks "Connect MetaMask". MetaMask prompts for wallet approval.
2
Register / Sign In
New users fill out the Registration form, selecting the "Document Sender" role. Existing users log in with their credentials. The system redirects to the correct role dashboard automatically.
3
Browse Print Shop Directory
The Sender Dashboard displays a searchable directory of verified print shops with location, rating, specialty, and shortened wallet address.
4
Upload PDF & Configure Job
The sender drags or browses for a PDF file. They configure print type (Color/B&W), number of copies, and job expiry duration using the settings panel.
5
Encrypt & Submit via MetaMask
The browser encrypts the file client-side and uploads the ciphertext to IPFS. MetaMask prompts the user to sign a blockchain transaction to register the print job on-chain.
6
Track & Manage Print Jobs
The dashboard displays active jobs with real-time statuses (Pending, Completed, Revoked) and allows the sender to revoke access at any time before printing.

🖨
Print Shop: Interaction & Printing Workflow

1
Register as Print Shop & Set Up Wallet
The shop operator registers with the "Printer Shop" role and visits Settings to register their MetaMask encryption public key on the smart contract.
2
Monitor Incoming Job Queue
The Print Shop Dashboard displays a real-time queue of pending jobs, showing sender address, document size, copies, print type, and expiry countdown.
3
Decrypt via MetaMask
The shop clicks "Print Job". MetaMask prompts for their signature to decrypt the wrapped AES key. The private key never leaves MetaMask's vault.
4
Secure Preview & Direct Print
The document is decrypted in RAM and rendered in a sandboxed iframe with toolbars hidden. Only the OS print dialog is accessible — no download or save buttons.
5
Confirm Print On-Chain
After printing, the shop clicks "Confirm Print". A blockchain transaction marks the job as Completed, and the Blob URL is revoked to clear RAM.

Responsiveness, Accessibility & Web3 Abstraction

Responsive Layout

  • Desktop (≥1280px): Full sidebar + main content two-column layout.
  • Tablet (768–1280px): Collapsible sidebar with hamburger icon.
  • Mobile (<768px): Single column; navigation collapses into bottom tab bar.

Accessibility (WCAG AA)

  • Semantic HTML5: <nav>, <main>, <article>, <header> used throughout.
  • Color contrast ratios meet WCAG AA minimum (4.5:1).
  • Keyboard navigable interactive elements with visible focus states.
  • ARIA roles on dynamic components (modals, status badges).

Abstracting Web3 Complexity

  • Transaction hashes are never shown to users; only human-readable status labels (Encrypting…, Uploading to IPFS…, Confirming on Blockchain…).
  • Public encryption key registration happens automatically when users visit the Settings page; users don't interact with raw keys.
  • Job statuses from smart contract enum values are translated into color-coded badges.
  • The MetaMask popup is triggered only at two natural decision points: job submission and decryption.

Ease of Use

  • Role-based redirection: users land directly on their dashboard after login.
  • Drag-and-drop file upload zone with file size preview.
  • One-click revocation with instant on-chain confirmation.

🔐 PrivyPrint

PrivyPrint successfully demonstrates that physical document printing can be made genuinely secure, private, and trustless by leveraging the core pillars of Web 3.0 technology. Through client-side AES-256 encryption, decentralized IPFS storage, and immutable on-chain access governance via Solidity smart contracts, the system ensures that sensitive documents exist as plaintext only in the user's browser and — briefly — in the print shop's volatile RAM at the exact moment of printing. No plaintext data is ever stored on a central server, in a cloud database, or on a print shop's hard drive.

PrivyPrint not only solves a real, underserved security problem but does so while providing a premium, glassmorphic user experience that abstracts away Web3 complexity, making decentralized technology accessible to everyday users and print shop operators alike.
